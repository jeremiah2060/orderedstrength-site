## What was built

**The share card, `/receipt/` and `/es/receipt/`.** A page that reads a sealed prediction receipt
out of the `?r=` URL parameter, decodes it from base64url in the browser, and lays it out: the
exercise, the predicted band, the naive baseline it was measured against, the session date, and the
commitment hash. With no parameter it shows an honest empty state rather than a broken card. Kilogram
fields arrive as integers scaled by 10,000 and are divided back down for display; the sealed
timestamp is Unix seconds rendered in the page's own locale, `es-419` on the Spanish side.

**The printable specification, `/spec/` and `/es/spec/`.** One page that says what the product is,
gives the technical grid (platform, where computation happens, whether an account is required,
commitment scheme, nonce, daily anchor, timestamp proof), states what the cryptography actually
proves, and ends with contact and status. It carries its own `@media print` block so it prints as a
clean document on white paper, and a Print button that calls `window.print()`.

**The design notes, `/design/` and `/es/design/`.** The colour tokens with live swatches, the
one-light model and its edge tokens, the three typefaces with samples, the layout token table, and
the design principles written out.

Three supporting files moved with them. `tools/lang-redirect-gate.mjs` grew its `PAIRS` array from
ten pairs to thirteen, so the loop-freedom test walks the new pages rather than generalising from
the old ones. `sitemap.xml` gained six entries, each with its `xhtml:link` hreflang alternates.
`_headers` was regenerated by `tools/csp-hashes.py` and now names twelve inline scripts where it
named nine, which `csp-hashes.py --check` confirms.

## What was fixed this session

**The optical size mismatch on both spec pages.** `span.spec-url` was set at `.8125rem`, and the
gate measures what the browser renders rather than what the stylesheet says: IBM Plex Mono at 13px
has an x-height of 6.71px sitting inside Public Sans at 15px whose x-height is 7.76px, which is
13.5% short against a 7% tolerance. It is now `.875rem`, measured at 6.8% short, and `TYPE OK`
prints at both 1440px and 390px.

**The print block on both spec pages was fighting the shared sheet.** Its `@media print` redeclared
`.bar`, `.skip`, `.foot`, `body` and `.scene`, every one of which `assets/site.css:1345` already
handles for the whole site. Those five are gone and only the spec-specific print rules remain, so
the page no longer silently beats the stylesheet it inherits from.

### 1. Shadowed declarations, 2 failures

`receipt/index.html` and `es/receipt/index.html` both declare a bare `.card`, and
`assets/site.css:688` already owns that selector. The page style silently wins, which is exactly
the class of defect this gate exists to catch.

The fix is the rename that was reported and never happened. In both files, in the `<style>` block,
line 2 is `.card{max-width:48rem;...}`, line 5 is `.card.unset`, and line 8 is
`.card.unset .card__eyebrow`. In the markup, `receipt/index.html:111` is `<div class="card">` and
there are six `class="card` sites per file. Rename the bare container to `.rcard` and leave every
`.card__*` child exactly as it is: those are distinct selectors that appear nowhere in `site.css`
and they shadow nothing. The compound `.card.unset` becomes `.rcard.unset`, and
`.card.unset .card__eyebrow` becomes `.rcard.unset .card__eyebrow`.

Verify by grepping for a `.card` that is not followed by two underscores, in the style block and in
the markup separately. A count of remaining `.card` occurrences is not a verification, because the
children legitimately keep the name and will keep the count non-zero.

### 2. Parallel text, 2 failures

`es/spec/index.html:117` renders `iPhone (iOS 17+)` and `:124` renders `32 bytes CSPRNG`, both
byte-identical to the English page. The gate reads an identical Spanish string as an untranslated
one, and here it is wrong: a product name and a cryptographic unit are the same in both languages
and translating either would be worse Spanish, not better.

So the fix is to say so in the markup rather than to invent a translation. Mark both values
`translate="no"`, which is the mechanism the rest of the site already uses for the wordmark and the
language links, and which the notranslate gate already understands.

### 3. Type floor, 12 failures

Three selectors on the design pages render at 11px against a 12px floor, and each is measured at
both 390px and 1440px on both language pages, which is how three defects become twelve failures.
They are `.swatch__hex`, `.swatch__note` and `.type-label`, all set to `.6875rem`, at
`design/index.html` lines 60, 61 and 65 and `es/design/index.html` lines 45, 46 and 48.

Raise all six declarations to `.75rem`. Do not reach for the gate's exemption list: that mechanism
exists for marks with no reading role, it demands a written reason per entry, and all three of
these are read. `.swatch__note` carries a sentence ("The room. Page background."), `.swatch__hex`
carries a hex code somebody is meant to copy, and `.type-label` names a token. The gate's own
header states the floor and why 11px was judged a squint on a dark ground, and it was written after
the CEO looked at the footer and said the fonts were too small.

## The order to work in

Fix the three gates above, then run `./check.sh` once and read it whole. Do not run it after each
fix: the suite drives a browser across twenty-six pages at six widths and one run answers all three
questions at once.

`stamp-assets.py` and `tools/csp-hashes.py` do not need re-running for any of the three fixes. All
three change CSS inside `<style>` blocks or add a `translate` attribute, and the hash tool reads
`<script>` blocks while the stamper rewrites `/assets/` URLs. Neither input moves. Run
`csp-hashes.py --check` at the end anyway, because it is instant and it is the one gate whose
failure mode is a page that silently does nothing in a browser.

Then commit and push. **The push is the only step that ships**, and the six page directories are
untracked, so they need naming explicitly. Never `git add .` here: the repository root holds
handoffs and scratch files that do not belong in a deploy.

```
git add receipt/ es/receipt/ spec/ es/spec/ design/ es/design/ \
        _headers sitemap.xml tools/lang-redirect-gate.mjs
git commit
git push origin main
```

After the push, verify against the domain rather than against the build log. Curl the six new paths
and confirm a 200 with real content: production has historically returned a 2,555-byte placeholder
with a 200 status for every path that does not exist, so a 200 alone proves nothing. Check the byte
count, or grep the response for a string only the new page contains.

## What could not be built here, and why

**The G1 photograph.** The 2026-09-02 list asks for a real screenshot of Jerry cutting a set in the
middle of a session. That needs the simulator running the app and a session driven to the point
where a cut actually happens. It is a photograph of behaviour, not a file that can be authored, and
it stays owed.

**The Swift anchor client.** The `URLSession` code that sends a sealed `PredictionCommitment` to the
anchor endpoint can be written, but it cannot be verified against anything, because `server/deploy.sh`
has never been run. That deploy needs `fly secrets set GITHUB_ANCHOR_TOKEN=...` first, which is a
credential and an external service, so it sits on the CEO side of the boundary rather than this one.

🔒 **AND THERE IS A STANDING LAW ABOUT WRITING A CLIENT FOR A ROUTE NOBODY HAS CURLED.** The
verifier route was built, pinned to a cross-language golden vector, committed, and never deployed,
and `POST /api/v1/verify` returned 404 on the live fleet for weeks while the source was correct the
whole time. Before the anchor client names an endpoint, curl the endpoint. A route in `index.js` is
a claim about this repository and never about the fleet.
